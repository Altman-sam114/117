## 背景与现状

`MDJournal/Views/EntryEditorView.swift` 的编辑器头部当前使用：

```swift
DatePicker("", selection: $entry.createdAt, displayedComponents: .date)
    .labelsHidden()
    .datePickerStyle(.compact)
```

该控件保留了 compact 样式和 `createdAt` binding，但它的 label 是空字符串。`.labelsHidden()` 只用于隐藏 label 的视觉呈现，SwiftUI 仍会将非空 label 作为系统控件语义暴露给 VoiceOver；因此正确修复是给 `DatePicker` 本身提供稳定且有意义的 label，继续使用 `.labelsHidden()` 保持当前视觉布局，不另造可见文字或手写日期值文案。日期值、可调整特性和当前选择状态继续由系统 `DatePicker` 负责读取。

现有 `MarkdownSnippetTests.swift` 已承载编辑器写作命令、工具栏文案与辅助功能纯契约测试。将本轮日期 label 契约测试放入该现有文件，比放入数据模型边界的 `JournalEntryTests.swift` 更符合职责，也可避免新增测试文件和修改 Xcode 工程。

## 本轮目标

1. 为编辑器头部 `DatePicker` 提供精确且稳定的中文 label：`日记日期`。
2. label 必须由 `EntryEditorView.swift` 内一个极小、无状态、内部可测的纯契约常量提供，`DatePicker` 必须直接消费该常量，不得为测试和视图各写一份文案。
3. 继续使用 `.labelsHidden()`，保持头部当前紧凑视觉布局；隐藏的系统 label 仍用于 VoiceOver 字段名称。
4. 保留 `.datePickerStyle(.compact)`、`$entry.createdAt` binding 和 `displayedComponents: .date`，日期值继续由系统控件按当前 locale 与辅助功能设置朗读。
5. 新增一项确定性 XCTest，同时断言契约值精确等于“日记日期”且去除空白后非空。
6. 保持日期编辑引发的既有 Store update、`createdAt` 变化时排序、短延迟合并保存和本地 JSON 持久化链路不变。
7. 将 GitHub Actions 结果包版本更新为 `v0.70`，同步受影响文档，并由 Agent C 下载最新未加密 artifact 复判。

## 纯契约设计

在 `EntryEditorView.swift` 文件顶层、`EntryEditorView` 之前定义一个内部可见、无状态的极小契约：

```swift
enum EntryEditorAccessibilityContract {
    static let journalDateLabel = "日记日期"
}
```

精确要求：

- 类型和常量不得声明为 `private`，以便现有 test target 通过 `@testable import MDJournal` 访问；也不得声明为 `public` API。
- 契约只包含本轮需要的 `journalDateLabel`，不把其他编辑器文案、布局尺寸、颜色或日期格式搬入该类型。
- `DatePicker` 必须直接消费 `EntryEditorAccessibilityContract.journalDateLabel`，禁止在视图内继续保留空 label，禁止另写字面量“日记日期”绕过契约。
- 不引入通用 localization 系统、设计系统或新抽象；当前项目为中文 UI，本轮只锁定已指定文案。

## `DatePicker` 精确接线

将现有控件改为：

```swift
DatePicker(
    EntryEditorAccessibilityContract.journalDateLabel,
    selection: $entry.createdAt,
    displayedComponents: .date
)
.labelsHidden()
.datePickerStyle(.compact)
```

以下约束必须同时成立：

1. `DatePicker` 的第一个参数是契约常量，值为精确的“日记日期”。
2. `.labelsHidden()` 保留，且不添加额外可见 label，因此头部布局不增宽、不换行、不改变高度。
3. `.datePickerStyle(.compact)`、`selection: $entry.createdAt` 和 `displayedComponents: .date` 逐字语义保留。
4. 不添加 `.accessibilityLabel(...)` 或 `.accessibilityValue(...)` 重复覆盖系统 `DatePicker` 的 label/值组合；标准 label 就是本轮的 accessibility 名称来源。
5. 不对 `DatePicker` 添加 `.accessibilityHidden(true)`、不移除系统可调整特性，不手工朗读或格式化 `entry.createdAt`。
6. 不触碰同一 `HStack` 的 `categoryPicker`、`moodPicker`、`Spacer(minLength: 8)` 或其他 modifier。

## 风险

- `.labelsHidden()` 按 SwiftUI 标准语义隐藏视觉 label 而保留辅助功能名称，但纯契约测试无法检查当前系统实际 accessibility tree；需后续人工 VoiceOver 验收。
- 系统 `DatePicker` 的日期值朗读依赖 locale、calendar、系统版本和 VoiceOver 语言；本轮刻意不手工固化值文案，以避免与系统语义分叉。
- 单元测试只锁定常量；若未来视图不再消费该常量，测试自身不会检测脱节，因此本轮必须由 Agent B 和 Agent C 审查直接接线。
- 虽然 label 视觉隐藏，仍需在真实 iPhone/iPad/Mac Catalyst 上检查头部窄屏、横屏、Dynamic Type、focus ring 和日期弹出交互。
- 本轮不改写入性能路径；Store update、按需排序和保存节流仅作为回归边界保持，不得把本轮说成新的性能优化。
