## 2. 背景与问题定义

当前 `MDJournal/Views/EntryEditorView.swift` 的相关事实：

- `GeometryReader` 中使用 `proxy.size.width >= 820` 同时影响编辑/预览分栏和头部布局，没有读取 `dynamicTypeSize`。
- 头部第一行用一个 `HStack` 强制分类、心情和日期保持同行。
- 宽屏头部用横向统计 / 小节概览布局，并把统计区域固定为 `270pt`。
- `EditorStatPill` 强制 `.lineLimit(1)`。
- 标题最多两行。
- 小节卡片固定外宽 `156pt`，excerpt 又固定内宽 `132pt`，并使用很小的 `.caption2`。
- 因此即使 Mac Catalyst 窗口足够宽，只要用户使用 Accessibility Dynamic Type，头部仍按普通宽屏横排，分类、心情、日期、统计 pill、标题和小节摘要可能被压缩或裁切。

本轮要明确拆开两个决策：

1. **编辑器工作区是否宽屏分栏**：仍只由容器宽度和统一的 `820pt` 边界决定，保持现有 Mac Catalyst 编辑/预览双栏行为。
2. **编辑器头部是否横向紧凑排列**：同时取决于宽度和 Dynamic Type。只有普通字号且宽度达到 `820pt` 才使用现有紧凑横排；窄屏或任何 Accessibility 字号都使用可自然增高的堆叠布局。

这两个决策不能再共用一个含义模糊的 `isWideLayout` 布尔值。Accessibility 字号下，宽窗口仍可保留编辑/预览分栏，但头部必须堆叠。

## 3. 本轮目标

1. `EntryEditorView` 消费 `@Environment(\.dynamicTypeSize)`，以当前容器宽度和 Dynamic Type 共同派生头部布局。
2. 新增 internal、纯值、无副作用、可由 `@testable import MDJournal` 访问的 `EntryEditorLayoutContract`，统一维护 `820pt` 边界、布局轴、可选固定统计宽度、行数策略和小节卡片基准尺寸。
3. 保持 `820pt` 的编辑/预览分栏边界不变；`819pt` 是 compact editor，`820pt` 是 wide editor，不受 Dynamic Type 改变。
4. 普通字号且宽度达到 `820pt` 时，保留安静、紧凑的宽屏头部：元数据横排，统计与小节概览横排，统计区域可继续使用 `270pt` 宽度。
5. 窄屏或 Accessibility 字号下，分类、心情、日期不再被强塞在同一行；统计与小节概览堆叠。Accessibility 字号下统计 pill 也应堆叠，并取消 `270pt` 固宽。
6. Accessibility 字号下标题允许自然增加行数；统计 pill 不得继续用单行截断隐藏内容。
7. 小节 excerpt 从 `.caption2` 提升到 `.caption`；卡片宽度采用 `@ScaledMetric` 或同等明确的 Dynamic Type 可缩放策略，并删除固定 `132pt` 内层宽度。
8. 保持现有 entry binding、日期编辑、分类 / 心情菜单、Markdown 正文、预览、工具栏、菜单命令、颜色、背景和本地保存链路不变。
9. 在现有最合适测试文件中新增纯 contract 测试，确定性覆盖 `819/820pt × .large/.accessibility1/.accessibility5` 矩阵、行数策略和正尺寸常量。
10. workflow 仅把 `VERSION: v0.73` 更新为 `VERSION: v0.74`，由云端执行 generic iOS build、Mac Catalyst build 和 XCTest。

## 5. 架构依据与状态边界

- `EntryEditorView` 仍是标题、元数据、正文、编辑 / 预览布局和 Markdown 快捷入口的唯一视图边界。
- `EntryEditorLayoutContract` 只接收容器宽度和 `DynamicTypeSize`，输出布局决策与尺寸常量；它不能读取或修改 `JournalEntry`、Store、环境对象、焦点、选区或持久化状态。
- contract 必须是 internal 纯值类型，不能声明为 `private`（测试不可访问），也不能声明为 `public`（不增加公共 API）。
- 宽屏工作区决策和头部紧凑决策必须分离：
  - `isWideEditorLayout` 只看 `width >= 820`。
  - 紧凑头部只在 `isWideEditorLayout && !dynamicTypeSize.isAccessibilitySize` 时成立。
- 视图必须直接消费被测试的 contract。禁止创建一个只供测试使用、实际视图仍自行判断 `820` 或 `isAccessibilitySize` 的假契约。
- `@Environment(\.dynamicTypeSize)` 只影响非持久化布局；禁止把字号或布局模式写入 `JournalEntry` 或 JSON。
- 允许在 `EntryEditorView.swift` 内增加少量 internal contract / enum，因为现有编辑器 UI 契约已经在该文件内，并由现有 test target 通过 `@testable import` 访问。本轮不为纯布局契约新增 Swift 文件或修改 Xcode project。
- 使用语义字体和 `@ScaledMetric`，不通过屏幕宽度计算字体大小，不使用 `UIScreen.main.bounds`，不添加硬编码自定义字号。

## 7. 建议的纯布局契约

名称固定建议为：

```swift
internal struct EntryEditorLayoutContract: Equatable {
    // 纯布局输入和决策
}
```

可以增加一个极小的 internal 轴枚举，例如：

```swift
internal enum EntryEditorLayoutAxis: Equatable {
    case horizontal
    case vertical
}
```

建议 contract 至少集中表达以下信息；属性名可以按现有代码风格微调，但语义和测试覆盖不能丢失：

- `static let wideLayoutMinimumWidth: CGFloat = 820`
- `static let regularWideStatisticsWidth: CGFloat = 270`
- `static let sectionCardBaseWidth: CGFloat = 156`
- `isWideEditorLayout`
- `usesCompactHeaderLayout`，只在普通字号且宽度 `>= 820` 为 `true`
- 元数据布局轴：普通宽屏为 horizontal，窄屏或 Accessibility 为 vertical
- 统计 / 小节概览布局轴：普通宽屏为 horizontal，窄屏或 Accessibility 为 vertical
- 统计 pill 布局轴：Accessibility 为 vertical；普通字号可保持 horizontal
- `statisticsWidth: CGFloat?`：只在普通宽屏返回 `270`，其余为 `nil`
- `titleLineLimit: Int?`：普通字号保持 `2`；Accessibility 返回 `nil`，允许标题自然增长
- 小节标题 / excerpt 行数策略：普通字号可保留现有 `1 / 2`；Accessibility 至少增加到 `2 / 3`，不得比普通字号更少

初始化建议：

```swift
init(width: CGFloat, dynamicTypeSize: DynamicTypeSize)
```

精确约束：

- contract 不保存 View、Binding、Color、closure、`JournalEntry` 或其他可变状态。
- 所有尺寸常量必须大于 0；`wideLayoutMinimumWidth` 精确等于 `820`，`regularWideStatisticsWidth` 精确等于现有 `270`，`sectionCardBaseWidth` 精确等于现有外卡片 `156`。
- `820` 不得继续散落在 `EntryEditorView.body` 的独立判断中；工作区和头部都从同一个 contract 读取。
- 不为 `132` 保留另一个常量；固定内层 excerpt 宽度必须删除。
- 不需要把所有 padding、圆角、颜色和 toolbar 尺寸搬进 contract。contract 只承载本轮真实布局分支和被测试的必要常量。
- 不允许把 Dynamic Type 判断写成 `.accessibility1` 的单点比较；必须使用 `dynamicTypeSize.isAccessibilitySize`，从 AX1 到 AX5 全覆盖。

## 8. UI 行为矩阵

以下矩阵是本轮的权威行为，不得用“看起来差不多”替代：

| 容器宽度 | Dynamic Type | 编辑 / 预览工作区 | 元数据（分类/心情/日期） | 统计与小节概览 | 统计 pill | 统计固定宽度 | 标题 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `819` | `.large` | compact，单栏编辑/预览切换 | vertical，不强塞同一行 | vertical | horizontal 可保留 | `nil` | 最多 2 行 |
| `820` | `.large` | wide，编辑/预览双栏 | horizontal | horizontal | horizontal | `270` | 最多 2 行 |
| `819` | `.accessibility1` | compact | vertical | vertical | vertical | `nil` | 不设上限 |
| `820` | `.accessibility1` | wide，双栏保持 | vertical | vertical | vertical | `nil` | 不设上限 |
| `819` | `.accessibility5` | compact | vertical | vertical | vertical | `nil` | 不设上限 |
| `820` | `.accessibility5` | wide，双栏保持 | vertical | vertical | vertical | `nil` | 不设上限 |

补充要求：

- 宽屏 Accessibility 不能因为头部堆叠而错误切回 compact editor；编辑 / 预览分栏仍由宽度独立决定。
- 窄屏普通字号不再把分类、心情和日期三者压在同一行；纵向空间增加是本轮为可读性接受的取舍。
- 元数据堆叠时每个控件保持自然宽度和 leading 对齐，不用固定高度或缩小字体强行塞入。
- `DatePicker` 必须继续直接消费 `EntryEditorAccessibilityContract.journalDateLabel`，保留 `.labelsHidden()`、`.datePickerStyle(.compact)`、`selection: $entry.createdAt` 和 `.date` components。
- 普通宽屏外观应尽量保持现状：`270pt` 统计区、横向元数据、横向统计 / 小节概览和两行标题均保留。

## 9. 视图实现要求

### 9.1 环境与单次 contract 派生

在 `EntryEditorView` 中增加：

```swift
@Environment(\.dynamicTypeSize) private var dynamicTypeSize
```

在 `GeometryReader` 的单次 body 计算中创建 contract：

```swift
let layout = EntryEditorLayoutContract(
    width: proxy.size.width,
    dynamicTypeSize: dynamicTypeSize
)
```

后续工作区分栏、`isWideLayoutActive` 同步和 header 都消费 `layout`。禁止同时保留另一个 `proxy.size.width >= 820` 判断。

`isWideLayoutActive` 仍只保存工作区是否 wide，用于现有 Mac 预览切换和专注写作命令；不能改成“紧凑头部是否启用”。

### 9.2 元数据布局

- 普通宽屏保持分类、心情、Spacer、日期的横向视觉。
- 窄屏或 Accessibility 使用纵向布局，让分类、心情、日期分别获得自然宽度；不得通过 `.minimumScaleFactor`、固定高度、缩小字号或水平裁切维持单行。
- 可使用小范围 `if` 分支或 `AnyLayout`，但必须保证分类、心情和日期仍是同一组原有控件，不复制或改写 binding / action。
- 保持 category / mood menu 的原文字、图标、tint、背景和交互；只改变容器布局。

### 9.3 标题

- 普通字号继续 `.lineLimit(2)`。
- Accessibility 字号不设置上限，允许标题 TextField 自然增高。
- 保持 `TextField("今天的标题", text: $entry.title, axis: .vertical)`、plain style、title2 语义和 entry binding。
- 不引入字符限制、自动缩小字体或固定高度。

### 9.4 统计与小节概览

- 普通宽屏继续横排；统计区域可使用 `layout.statisticsWidth == 270`。
- 窄屏或 Accessibility 堆叠统计与 `JournalSectionOverview`。
- Accessibility 下 `statisticsWidth` 必须为 `nil`，不能把 `.frame(width: 270)` 留在视图的无条件路径。
- 统计 pill 在 Accessibility 下纵向排列；普通字号可保持横向。
- 删除 `EditorStatPill` 的 `.lineLimit(1)`，或用 contract 明确提供不截断策略；不得用 `.minimumScaleFactor` 隐藏问题。
- pill 可自然增高，图标、value 和 title 保持原语义与颜色，不改数值口径。

### 9.5 小节卡片

- `JournalSectionOverview` 中 excerpt 字体从 `.caption2` 改为 `.caption`。
- 使用 `@ScaledMetric(relativeTo: .caption)` 为卡片宽度提供 Dynamic Type 缩放，wrapped value 直接来自 `EntryEditorLayoutContract.sectionCardBaseWidth` 或等价单一常量。
- 保留横向 `ScrollView` 和 `LazyHStack`，不要改为 eager stack 或网格。
- 删除 excerpt 的 `.frame(width: 132, ...)`；卡片只保留一个可缩放的外部宽度约束，内部文本使用可用内容宽度。
- 普通字号可以保持小节标题 1 行、excerpt 2 行；Accessibility 至少允许标题 2 行、excerpt 3 行。
- 不改变 section 顺序、title、excerpt 内容、accent、背景、边框或 `###` 小节识别。
- 所有固定格式元素必须保持稳定宽度策略，hover、Dynamic Type 或内容变化不能让卡片宽度在同一字号下跳动。
