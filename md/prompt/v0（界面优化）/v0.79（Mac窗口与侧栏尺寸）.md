# v0.79：Mac 窗口与侧栏尺寸

## 版本分配依据

- 当前 `origin/main` 已完成 `v0.78` 正文 metrics 单次扫描；下一轮沿 `v0.x` 小版本递增为 `v0.79`。
- 本轮由 Agent X 根据 Agent A 的代码审查选择 Mac Catalyst 主窗口和 sidebar 尺寸契约，范围独立于 v0.78 的正文派生实现。

## 背景

- `MDJournalApp` 目前只为 Catalyst 统计窗口设置尺寸，主 `WindowGroup` 没有最小内容尺寸。
- `ContentView` 的 `NavigationSplitView` 没有 sidebar 宽度约束；编辑器以 detail 宽度 `820pt` 决定单栏或编辑/预览双栏。
- Mac 窗口初始过窄或 sidebar 被拖宽时，写作空间可能不足以稳定进入宽屏编辑器，影响桌面端长文写作。
- 当前工程必须继续兼容 iOS 16.0 和 Mac Catalyst 13.0，不提高 deployment target，不新增独立 native macOS target。

## 目标

1. 为 Catalyst 主窗口增加明确的最小内容尺寸，目标为 `1120pt × 720pt`。
2. 为 Catalyst sidebar 增加 `260pt` 最小、`300pt` 理想、`360pt` 最大宽度约束。
3. 保证理想布局满足 `300pt sidebar + 820pt detail` 的宽屏编辑器边界，并为分隔线保留合理余量。
4. 用纯值尺寸契约测试锁定常量关系，不把测试伪装成真实窗口拖拽或像素验证。

## 非目标

- 不修改 iOS/iPadOS 的窗口或 sidebar 行为。
- 不修改 `JournalStore`、JSON schema、兼容解码、selection/filter、保存 debounce/flush、正文 binding、Markdown 解析或预览语义。
- 不新增键盘快捷键，不修改 focused scene value、菜单命令、编辑器焦点和写作状态。
- 不使用 `.defaultSize` 等可能超出 Mac Catalyst 13 可用范围的 API，不修改 deployment target。
- 不引入第三方依赖，不创建分支、PR 或候选分支，不扩大为独立 native macOS target。

## 架构依据

- `MDJournalApp` 是 Scene/WindowGroup 入口；主窗口只在 `targetEnvironment(macCatalyst)` 下附加尺寸约束，iOS 路径保持原样。
- `ContentView` 负责应用级导航；sidebar 宽度 modifier 只附加在 Catalyst 的 `EntryListView` 上，detail 和选中状态仍由现有 `ContentView` 管理。
- `EntryEditorLayoutContract.wideLayoutMinimumWidth` 是当前 `820pt` 宽屏边界，不能在本轮复制或修改该规则。
- 新增内部 `MacWindowLayoutContract` 只保存非持久化布局常量和最小关系，视图与测试共享同一来源，避免测试硬编码另一套数值。

## 影响范围和关键文件

- `MDJournal/MDJournalApp.swift`：新增内部尺寸契约；Catalyst 主 `WindowGroup` 附加最小宽高。
- `MDJournal/ContentView.swift`：Catalyst sidebar 使用 `navigationSplitViewColumnWidth(min:ideal:max:)`；iOS/iPadOS 分支不附加 modifier。
- `MDJournalTests/MarkdownSnippetTests.swift`：增加尺寸常量、正有限值、sidebar 范围和 `300 + 820` 关系测试。
- `README.md`、`md/test/test.md`、`md/flow/flow.md`、`md/flow/flowchart.md`、`update_log.md`：记录当前 Catalyst 主窗口与 sidebar 真实边界、云端结果和人工验收遗留事项。
- `.github/workflows/ci-results.yml`：将结果包版本更新为 `v0.79`。

## 实现步骤

1. 开始前在 `main` 上同步最新 `origin/main`，确认 HEAD 为本轮实现起点且工作区没有无关改动。
2. 在 `MDJournalApp.swift` 增加内部 `MacWindowLayoutContract`，至少提供最小窗口宽度、高度、sidebar min/ideal/max 和 detail 宽屏边界关系所需常量；不改变数据模型。
3. 在 Catalyst 编译分支给主 `ContentView` 加 `.frame(minWidth:minHeight:)`，使用契约常量；不要让该 modifier 出现在 iOS/iPadOS 路径。
4. 在 `ContentView` 的 sidebar 分支给 `EntryListView` 加 `.navigationSplitViewColumnWidth(min:ideal:max:)`，只在 Catalyst 生效；detail 仍消费现有 selection binding 和 `EntryEditorView`。
5. 在 `MarkdownSnippetTests` 增加纯契约断言：常量有限且为正、`min <= ideal <= max`、理想窗口宽度至少覆盖理想 sidebar 加 `EntryEditorLayoutContract.wideLayoutMinimumWidth`，并锁定 `1120/720/260/300/360`。
6. 只做必要文档同步；不要把人工交互风险写成 CI 已验证。
