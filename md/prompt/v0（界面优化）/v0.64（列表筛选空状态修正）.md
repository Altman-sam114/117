# v0.64 / 列表筛选空状态修正

## 版本号

`v0.64`

## 版本分配依据

当前最新正式版本是 `v0.63`。用户总目标已扩展到全面优化界面与 UI，本轮沿 `v0.x` 递增，修复列表在搜索或分类筛选无结果时显示错误空状态的问题。

## 背景

`EntryListView.listEmptyState` 当前只根据 `searchText.isEmpty` 判断“还没有日记”或“没有找到日记”。当仓库已有日记，但用户选择一个计数为 0 的分类时，`searchText` 仍为空，界面会误显示“还没有日记”和“写一篇”，掩盖真正原因是筛选条件没有结果。

## 目标

- 让 `JournalEntryListSnapshot` 明确暴露当前日记集合是否为空。
- 集合真实为空时继续显示“还没有日记”和“写一篇”。
- 集合非空但搜索或分类筛选结果为空时显示“没有符合条件的日记”，并提供“清除筛选”操作，同时重置搜索文本和分类。
- 补充 snapshot 单元测试，锁定集合空状态与筛选空结果的区别。
- 更新 workflow `VERSION` 为 `v0.64`，同步 README、测试规范、核心流程、流程图和更新日志。

## 非目标

- 不改变搜索匹配、分类计数、列表排序、删除、新建或选中项语义。
- 不重做列表视觉主题，不改编辑器、统计、Markdown、JSON 持久化或 Mac Catalyst target。
- 不引入第三方依赖。
- 不运行本机完整 build、XCTest、模拟器或 app；最终以 GitHub Actions artifact 验收。

## 架构依据

- `JournalEntryListSnapshot` 负责列表筛选派生，是判断“集合为空”与“筛选为空”的唯一可靠输入。
- `EntryListView` 只消费 snapshot 并展示空状态，不复制搜索或计数逻辑。
- `JournalEntryListSnapshotTests` 已覆盖筛选与分类计数，本轮继续在同一测试文件锁定空状态分类。

## 实现步骤

1. 为 `JournalEntryListSnapshot` 增加只读 `isCollectionEmpty`，由 `totalCount == 0` 派生。
2. 将 `EntryListView.listEmptyState` 改为接收 snapshot；根据 `isCollectionEmpty` 选择图标、标题和操作。
3. 新增 `clearFilters()`，同时清空 `searchText` 与 `selectedCategory`。
4. 集合为空时保留“写一篇”按钮；筛选为空时展示“清除筛选”按钮。
5. 增加空集合和分类筛选无结果 tests。
6. 同步 workflow 版本号和文档。
