## 背景

当前 `MDJournal/Views/EntryEditorView.swift` 在同一次 `body` 评估中已经取得 `let bodyMetrics = entry.bodyMetrics`（当前约第 93 行），该值来自 `MDJournal/Models/JournalEntry.swift` 的 `JournalEntryBodyMetrics` shared scan。编辑区域的 placeholder 仍走另一条路径：

- `bodyEditorArea` 当前通过 `bodyContainsVisibleContent` 判断是否显示“用 ### 小节组织今天的记录。”；
- `bodyContainsVisibleContent` 当前对整篇 `entry.body` 再执行 `contains { !$0.isWhitespace }`；
- Mac Catalyst 长文输入时，正文 binding 变化会让编辑器重新评估，先做一次 metrics 全文扫描，再做一次 placeholder 全文扫描。

相关现状证据：

## 本轮目标

1. 在非持久化的 `JournalEntryBodyMetrics` 中新增精确的 `hasVisibleContent`（或同等明确命名的内部字段）。
2. 让该字段在现有 `JournalBodyDerivation.scan` 的同一条正文 Character/Index 扫描中派生，避免为 placeholder 再遍历一次正文。
3. 让 `EntryEditorView` 在同一次 `body` 评估中把已经取得的 `bodyMetrics` 显式传到编辑区域，placeholder 只消费 `bodyMetrics.hasVisibleContent`。
4. 严格保持旧 placeholder 原语义：`body.contains { !$0.isWhitespace }` 的结果必须对所有 Character、Unicode 空白、换行、emoji、组合字符和标点一致。
5. 保持现有词数、小节、摘要、Markdown 预览、正文写回、焦点生命周期、保存和 JSON 行为完全不变。
6. 用纯值 XCTest 锁定 `hasVisibleContent` 与旧 closure 的逐输入等价性；不把测试计时、分配或 UI host 当作性能证据。

预期最小结果是 v0.82 的 `202` 项基础上新增一项契约测试，云端 XCTest 至少为 `203 passed / 0 failed / 0 skipped`；若实现保留现有其他测试数量，仍必须明确新测试实际执行且总数高于 `202`。

## 架构边界

- `JournalEntry` / `JournalEntryBodyMetrics` 是正文模型和非持久化派生边界；新增字段只存在于内存 `struct`，不参与 Codable。
- `JournalBodyDerivation` 是当前 v0.78 已建立的私有共享扫描边界。优先扩展其 `Result` 和既有扫描循环；不得在视图中复制模型扫描，也不得通过调用另一个完整 API 再扫正文。
- `JournalEntryBodyMetrics.init(body:)` 是本轮唯一需要消费 `hasVisibleContent` 的 metrics 生产入口；`wordCount(in:)` 和 `JournalSection.extract(from:)` 的兼容入口、签名和结果语义必须保留。

- `JournalStore` 仍是日记集合和本地持久化的唯一入口；本轮没有理由触碰它。
- `MarkdownPreviewView` 只消费 Markdown 解析结果；placeholder visible-content 与预览解析完全独立。

## 行为与语义保持要求

`hasVisibleContent` 的 oracle 必须是旧 placeholder 的 Character 级表达式：

~~~swift
body.contains { !$0.isWhitespace }
~~~

必须保持以下事实：

- 空字符串和完全由 `Character.isWhitespace == true` 组成的正文返回 `false`。
- 任意 `Character.isWhitespace == false` 的字符都返回 `true`，包括普通文字、数字、标点、`#`、反引号、emoji、组合字符和 Markdown 符号；不要求它们构成一个词或合法小节。
- `### `、只有标记、只有标点或只有代码围栏字符仍属于可见内容；可见性与 `JournalSection` 的 marker 合法性无关。
- 换行和 Unicode 空白的判断必须跟 `Character.isWhitespace` 一致；不能把 `Character.isNewline` 单独当成可见性规则，也不能用 `wordCount` 作为代理。
- 共享扫描新增的布尔值不得改变现有 `wordCount`、`sections`、section order/id/markdown/excerpt、摘要清理、overview metrics 或统计口径。
- `bodyMetrics.hasVisibleContent` 不得改变 placeholder 文案、MarkdownBodyTextView 的输入、selection/focus 写回或保存时序。

## 风险、验收边界与停止条件

### 主要风险

- `Character.isWhitespace` 与词数循环中的 `character.isWhitespace || character.isNewline` 是不同表达式；用 `wordCount` 或新增 `isNewline` 逻辑替代会在边界字符上改变 placeholder 语义。
- 在 `JournalBodyDerivation` 中新增 Result 字段时，若只更新 `JournalEntryBodyMetrics` 而未保持其他私有 scan 调用方的结果结构，可能造成编译断点或隐性重复扫描；必须用 Swift parse 和云端 build 检查所有调用方。
- 把 metrics 通过 computed property 或新的 `entry.bodyMetrics` 调用传入每个 helper，可能重新构造 metrics；要求 `body` 局部只创建一次，并显式向下传值。
- 纯值测试、云端编译和 XCTest 不能证明真实 Mac Catalyst 长文分配、帧率、输入延迟、first responder、IME marked text、VoiceOver、Dynamic Type 像素排版或 UI 命中区域；这些只能作为人工/专门工具的遗留验收，不得伪装成已验证。
- 任何对 JSON、Store、preview、focus 或 deployment 的无关 diff 都扩大风险并违反本轮边界。

### Agent X / Agent B 停止条件

遇到以下任一情况，应如实记录并停止当前轮次，不得用缩小目标或旧结果冒充完成：

- 必须改变旧 `Character.isWhitespace` placeholder 语义、词数、小节、摘要、Markdown 或 JSON 兼容行为才能通过。
- 必须修改 `JournalStore`、持久化 schema、预览 parser、焦点/窗口系统、deployment target、第三方依赖或用户数据。
- 工作区出现无法判断归属的冲突，无法确认 staged diff 只属于本轮，或无法从最新 `origin/main` 开始。
- GitHub Actions、GitHub 权限或 artifact 下载持续阻塞；同一阻塞连续 3 轮不得伪装通过。
- CI 因同一原因连续失败 3 轮，或连续 2 轮没有有效 diff。
- Agent C 无法核对最新 HEAD 的 manifest 身份、XCTest、artifact 未加密性或逐文件完整性。
- 需要人工产品决策、账号/密钥/付费服务，或人工要求停止/改变方向。

真实 Mac Catalyst UI、长文帧率、内存分配、IME、VoiceOver 或焦点时序无法由本轮 artifact 证明时，不是 v0.83 阻塞；应在文档中保留为明确的人工验收风险，不能写成云端已通过。
