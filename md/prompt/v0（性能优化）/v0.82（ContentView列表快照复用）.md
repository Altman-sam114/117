# v0.82：ContentView 列表快照复用

## 版本依据

- 当前最新正式版本为 v0.81，HEAD 为 `main@7a8f7b3`，v0.81 已完成预览焦点生命周期优化并通过 Agent C 云端 artifact 验收。
- v0.78 已将正文词数与完整小节派生合并为一次 shared scan；v0.80 已将列表概览的词数与 `###` 小节存在性合并为一次 overview scan。本轮不重复这两项正文扫描优化。
- v0.82 是当前 v0.x 阶段的下一个有限性能轮次，目标限定为 `ContentView` 一次 `body` 评估内的列表快照复用。

## 背景

`ContentView` 当前同时负责列表输入、选中项修复和 Mac Catalyst 日记导航。其 `body` 将 `listSnapshot` 传给 `EntryListView`；`journalEntryNavigationActions` 为较新和较早方向分别读取一次 `listSnapshot`；`selectedEntryBinding` 还会读取一次 `listSnapshot`。这些读取会重复初始化 `JournalEntryListSnapshot`。

`JournalEntryListSnapshot` 每次初始化都会遍历全部 entries，搜索文本非空时还会对标题、正文、分类和心情执行大小写不敏感搜索。Mac Catalyst 下切换选中项、输入搜索或触发视图重算时，重复构造的成本会放大，长正文搜索尤其明显。

当前 `overviewSnapshot` 在同一 `ContentView.body` 中只构造一次，并且已经消费 v0.80 的 `JournalEntryOverviewMetrics`；统计窗口单独构造 `JournalStatistics`，不属于本轮同一 body 重复派生问题。

## 目标

1. 在一次 `ContentView.body` 评估中只构造一份 `JournalEntryListSnapshot`。
2. 让 `EntryListView`、选中项 detail binding、较新/较早导航 actions 共用这份快照及其 `filteredEntries` 顺序。
3. 保持当前搜索、分类筛选、selection repair、创建/删除后选择修复和 Mac Catalyst 键盘导航行为完全不变。
4. 通过纯规则 characterization 测试锁定筛选后的可见顺序、selection repair 和相邻导航结果。
5. 保持实现为当前渲染周期内的局部复用，不新增跨渲染缓存、持久化字段或新的状态源。

## 非目标

- 不修改 `JournalEntryOverviewMetrics`、`JournalEntryBodyMetrics`、`JournalSection` 或任何 v0.78/v0.80 正文扫描算法。
- 不修改 `JournalListOverviewSnapshot`、`JournalStatistics`、统计窗口或统计口径。
- 不修改 `JournalStore`、JSON 编码、保存节流、创建、删除或排序逻辑。
- 不修改 Markdown parser、Markdown preview、`EntryRowView`、正文输入 bridge 或焦点生命周期。
- 不为列表快照增加持久化缓存、全局缓存、ObservableObject、actor 或基于时间的缓存失效机制。
- 不改变 `NavigationSplitView`、窗口尺寸、sidebar 约束、deployment target、菜单快捷键或 UI 文案。
- 不新增第三方依赖、独立 native macOS target、UI test target、截图测试、wall-clock 性能阈值或内存断言。

## 架构边界

- `ContentView` 仍是应用级导航、selection repair 和保存错误展示的唯一入口。
- `JournalEntryListSnapshot` 仍负责 entries 遍历、搜索、分类过滤和分类计数；本轮只复用其结果，不把过滤逻辑搬到视图或 Store。
- `EntryListView` 只消费传入的 `overviewSnapshot` 和 `JournalEntryListSnapshot`，不自行重新构造快照。
- `JournalEntryNavigation` 只消费当前可见 entries 的数组顺序；导航 actions 仍只修改 `selectedEntryID`。
- `JournalStore` 仍是日记集合唯一修改与持久化入口；ContentView 不得绕过 Store 批量修改数据。
- `JournalListOverviewSnapshot` 继续消费全部 entries，不能错误改成消费筛选后的 entries。

## 实现步骤

1. Agent B 开始前同步最新 `origin/main`，确认当前分支为 `main`、工作区没有无关改动，并核对 HEAD 不低于 `7a8f7b3`。
2. 在 `ContentView.body` 开头按当前 `store.entries`、`searchText` 和 `selectedCategory` 构造一次局部 `listSnapshot`。
3. 将该局部快照传给 `EntryListView`，并将导航 actions 和 selected detail binding 改为接收显式快照参数；这些 helper 不得在内部重新构造 `JournalEntryListSnapshot`。
4. 保留事件路径的即时正确性：`repairSelection()`、`createEntry()`、删除后的修复等方法在事件发生时可按需构造一次最新快照，不能捕获过期 body 局部值。
5. 保持 `selectedEntryBinding` 的 Store getter/setter、无效 selection fallback、可见 selection 判断和 `JournalEntrySelectionPolicy` 语义不变。
6. 保持 `journalEntryNavigationActions` 对筛选后 `filteredEntries` 的当前数组顺序求较新/较早目标；首尾不循环、隐藏 entry 不可达。
7. 不把 `overviewSnapshot` 改为筛选快照，也不让 `EntryListView` 重新计算列表或概览数据。
8. 更新测试和文档中的 v0.82 版本、真实影响范围和验证说明；不要伪造尚未产生的 run、artifact、digest 或测试结果。

推荐实现形态是 body 局部快照加显式参数 helper，不要求跨渲染缓存。局部变量可以在 SwiftUI body 重新评估时重新生成，但同一评估内不得重复初始化。

## 行为保持与 characterization 测试

新增或扩展纯 XCTest，重点覆盖与本轮复用直接相关的组合行为：

- 搜索过滤后，可见 entries 仍保持原有顺序；隐藏 entry 不出现在相邻导航目标中。
- 分类过滤后，列表快照、selection repair、较新导航和较早导航都只基于同一 `filteredEntries`。
- 当前 selection 有效时保持不变；selection 为空、无效或被筛选隐藏时仍回退到首个可见 entry。
- 空集合、单篇日记、首尾日记和无效 selection 的导航结果保持 `nil` 或现有目标。
- 搜索标题、正文、分类和心情的既有匹配语义保持；长正文只作为确定性 fixture，不使用计时断言。
- `overviewSnapshot` 的全部 entries 统计不因搜索或分类筛选而改变；可复用现有列表概览回归测试确认这一边界。

测试应验证结果语义，不通过 sleep、耗时阈值、内存峰值、视图 host、模拟器 UI 或 first responder 探针证明性能。静态 diff 检查负责确认 body 内只保留一次列表快照构造，XCTest 负责确认复用后的行为未变。

## 风险与禁止项

- SwiftUI 可能在不同状态变化下多次重新评估 `body`；本轮只承诺消除一次 body 评估内部的重复构造，不承诺跨评估缓存或固定帧率提升。
- `JournalEntryListSnapshot` 的搜索语义、分类计数和输入顺序必须保持；不得为了性能改变 `localizedCaseInsensitiveContains`、trim 规则或 fallback 标题行为。
- `overviewSnapshot` 必须继续使用完整 `store.entries`，不能错误复用筛选后的列表 entries。
- Binding 不能捕获过期的 `filteredEntries` 来读写 Store；只允许用快照做当前 selection 合法性判断。
- 不新增无测试依据的缓存失效规则、计时器、并发扫描、后台线程或数据模型字段。
- 不删除用户数据、不覆盖用户未说明改动、不修改 JSON 格式、不伪造测试、run、artifact 或人工 Mac 交互结果。
