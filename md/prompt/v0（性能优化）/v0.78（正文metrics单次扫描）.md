# Agent A 实现提示词：v0.78 / 正文 metrics 单次扫描

## 版本与起点

本轮版本为 `v0.78`，起点是 v0.77 最终文档 HEAD `2e5958f1e4849af72acf5df38578b8ba04647e30`。Agent B 必须先确认当前分支为 `main`，同步最新 `origin/main`，确认工作区没有无法判断归属的改动；不得回滚或覆盖其他 Agent 的修改，不改 remote、认证或凭据。

## 本轮目标

当前 `JournalEntryBodyMetrics` 先独立扫描正文词数，再调用 `JournalSection.extract(from:)` 扫描整篇正文，编辑器头部和列表等高频派生路径因此重复遍历长文。将模型层的 metrics 派生收敛为一次单调正文扫描，在同一条扫描路径中得到既有 `wordCount` 和 `sections`，减少重复扫描和不必要的中间派生。

必须保持公开/内部调用方的现有字段与行为：`wordCount`、`sections`、`sectionCount`、`JournalEntry.bodyMetrics`、摘要/列表/统计/编辑器展示均不改变。若实现需要内部结果值或私有 helper，应留在 `JournalEntry.swift` 的模型边界内，不把解析逻辑搬到视图或 Store。

## 兼容语义

- 保留 v0.77 `JournalSection.extract(from:)` 已锁定的 LF、CR、CRLF、VT、FF、NEL、LINE SEPARATOR、PARAGRAPH SEPARATOR 分行语义；CRLF 只能作为一个分隔处理。
- 保留行首连续 ASCII 空格/tab 后精确 `### ` marker 的识别规则；`###` 无分隔、`###\t`、`#### `、行内 marker、非 ASCII 空白前导均不得变成合法小节。
- 保留标题使用 `.whitespacesAndNewlines` trim、空标题回退为“未命名小节”、首个合法标题前正文忽略、标题命中先 flush、连续 marker/空正文/EOF/尾随换行和 section `order`/`id`/`markdown`/`excerpt` 语义。
- 不引入 fenced-code 状态机；围栏中的行首 `###` 仍按普通合法 marker 处理。不得复用 Markdown parser 的 fenced-code 语义替换模型小节规则。
- `wordCount` 必须逐字符/逐标量遵守现有 `JournalEntryBodyMetrics` 词数口径，包含 emoji、组合字符、Unicode 空白和尾随换行边界；不能以“看起来相同”的新分词规则替换旧规则。
- 共享扫描不得改变 `JournalSection.extract` 的独立 API 或 `containsLevelThreeSection` 快路径；如复用私有分行/flush helper，必须证明所有已有结果完全一致。
