# v0.66 / 列表概览小节检测快路径

## 版本号

`v0.66`

## 版本分配依据

- 当前 `main` 基线为 `81b1453`，最新正式版本为 `v0.65`。
- `v0.65` 已在遗留事项中把列表概览的小节检测路径列为下一轮优先性能目标；本轮继续服务 Agent X 总目标中的“优美写入、高效性能”，沿当前 `v0.x` 阶段递增为 `v0.66`。
- 本轮不增加新功能，而是移除正文编辑引发列表概览刷新时不必要的完整小节数组构造，属于边界清晰、可通过等价测试验收的性能优化。

## 背景

`JournalListOverviewSnapshot.init(entries:calendar:now:)` 当前为每篇日记读取 `entry.bodyMetrics`。`JournalEntryBodyMetrics.init(body:)` 会先调用 `JournalEntryBodyMetrics.wordCount(in:)` 扫描词数，再调用 `JournalSection.extract(from:)`：后者通过 `components(separatedBy: .newlines)` 为整篇正文构造行数组，并为每个合法 `### ` 标题收集正文行、拼接 Markdown，最终生成完整 `[JournalSection]`。

列表概览实际只消费 `bodyMetrics.wordCount` 和 `!bodyMetrics.sections.isEmpty`。用户编辑正文时，`MarkdownBodyTextView -> Binding<JournalEntry> -> JournalStore.update(_:) -> @Published entries -> EntryListView` 会重新派生概览；此时为全部日记生成完整小节对象、标题和 Markdown 是无效工作。更合适的路径是保留现有完整提取 API 给编辑器、列表行和预览等真正需要小节内容的调用方，同时为概览提供无数组分配、找到首个合法三级标题便返回的布尔谓词。

## 本轮目标

- 在 `JournalSection` 增加内部静态方法 `containsLevelThreeSection(in:) -> Bool`。
- 该谓词直接使用 `String.Index` 从头到尾单次向前扫描，不调用 `components(separatedBy:)`、`split`、`JournalSection.extract(from:)`，不构造行数组、标题字符串、正文行缓冲或 `[JournalSection]`。
- 谓词只在每行行首判断：跳过现有规则允许的前导 ASCII 空格和 tab 后，精确匹配 `### `；找到首个合法标题立即返回 `true`，扫描结束仍未找到则返回 `false`。
- `JournalListOverviewSnapshot` 分别调用 `JournalEntryBodyMetrics.wordCount(in: entry.body)` 和 `JournalSection.containsLevelThreeSection(in: entry.body)`，不再通过 `entry.bodyMetrics` 构造完整小节数组。
- 保持 `JournalSection.extract(from:)` 本身及其所有既有调用不变，保持列表概览的词数、`entriesWithSections`、`sectionCoverage`、分类聚合、连续记录、本周统计和洞察文案口径不变。
- 用 `JournalEntryTests` 的边界矩阵证明新谓词与 `!JournalSection.extract(from: body).isEmpty` 等价，并用必要的概览测试锁定聚合结果。
- 将 GitHub Actions 结果包版本更新为 `v0.66`，同步受影响文档。

## 非目标

## 架构依据

- `JournalEntry` / `JournalSection` 是正文小节语义边界。判定“是否至少存在一个按现有规则可提取的小节”的谓词应与 `JournalSection.extract(from:)` 放在同一类型中，避免概览自行复制一套不受约束的 Markdown 规则。
- `JournalEntryBodyMetrics.wordCount(in:)` 已是非分配词数扫描入口，应直接复用，不新增重复词数实现。
- `JournalListOverviewSnapshot` 是列表首页的轻量聚合边界，只应取得它真正消费的词数和小节存在性，不应构造完整正文 summary 或 section model。
- `JournalStatistics` 保持统计看板计算边界；本轮通过结果等价测试保证概览口径不漂移，不把统计逻辑搬入视图。
- `JournalStore` 仍是唯一日记集合修改和本地持久化入口，本轮不进入保存边界。

## 精确语义契约

新谓词必须与当前 `JournalSection.extract(from:)` 的“是否存在小节”语义等价：

- 文档开头和任意换行后的下一位置都视为行首。
- 行首只跳过 ASCII 空格 ` ` 和 tab `\t`；不把其他 Unicode 空白扩展为可忽略前导字符。
- 跳过前导空格/tab 后必须精确出现四字符前缀 `### `。
- `###无空格`、`## `、`#### `、行中间出现的 `### ` 均不合法。
- `### ` 后标题为空或只有空白仍是合法小节；完整提取会使用“未命名小节”，谓词只需返回 `true`。
- LF、CR、CRLF 以及 `CharacterSet.newlines` 所覆盖的既有换行边界必须保持等价；不得只识别 LF。
- 尾随换行和连续空行不得制造小节，也不得漏掉其后的合法标题。
- fenced code 不构成特殊上下文；其中符合上述行首规则的 `### ` 继续返回 `true`，与当前 `extract` 一致。

## 实现步骤

1. 按 `AGENTS.md` 顺序阅读入口文档、本提示词、相关模型、概览、测试和 workflow。
2. 执行 `git fetch origin`、`git switch main`、`git pull --ff-only origin main` 和 `git status --short --branch`，确认从最新且无无关改动的 `origin/main` 开始。若不能 fast-forward、远端不可用或工作区有归属不明改动，记录阻塞并停止。
3. 在 `JournalSection` 中新增 `static func containsLevelThreeSection(in markdown: String) -> Bool`。方法保持 internal，供同一模块的概览和 `@testable` 测试使用，不新增公开 API。
4. 使用单调递增的 `String.Index` 扫描正文。维护“当前是否位于行首”或等价状态；在每个行首跳过连续 ` ` / `\t`，随后用索引检查精确 `### ` 前缀。不得先提取整行，不得创建 `[String]`、`[Substring]`、`JournalSection` 或 section markdown。
5. 换行识别必须覆盖当前 `components(separatedBy: .newlines)` 对“下一行行首”的有效语义。可使用 Foundation 的 `CharacterSet.newlines` 在当前索引之后寻找下一换行并继续，或使用经过等价测试证明覆盖 LF、CR、CRLF 和既有 Unicode newline 的直接索引扫描；无论采用哪种方式，索引只能前进，不能从头重复扫描。
6. 一旦匹配首个合法 `### ` 立即返回 `true`；到达 `endIndex` 返回 `false`。不要为标题内容做 trim 或构造标题，因为存在性不依赖标题文本。
7. 在 `JournalListOverviewSnapshot` 的 entry 循环中移除 `let bodyMetrics = entry.bodyMetrics`。改为从 `entry.body` 调用 `JournalEntryBodyMetrics.wordCount(in:)` 得到词数，并调用新谓词决定是否增加 `entriesWithSectionsValue`。循环其余日期、周统计、分类聚合和洞察逻辑保持逐行不变。
8. 在 `JournalEntryTests` 增加表驱动等价测试。每个 case 同时断言明确的期望 Bool，以及 `JournalSection.containsLevelThreeSection(in: body) == !JournalSection.extract(from: body).isEmpty`，避免两个实现同时错误仍通过。
9. 测试至少覆盖：空正文和纯空白；普通正文；`## `、`#### `、`###无空格`；文档开头合法 `### 标题`；空标题 `### `；前导一个/多个空格和 tab；其他 Unicode 前导空白不合法；行中间 `### ` 不合法；LF、CR、CRLF；连续与尾随换行；Unicode newline；多个小节；fenced code 内合法行首标题。
10. 在 `JournalListOverviewSnapshotTests` 检查现有概览与 `JournalStatistics` 等价测试是否已充分覆盖。增加一个最小聚合 case，混合合法前导空格/tab 标题和 `###无空格` / `#### ` 等非法标题，明确断言 `entriesWithSections`、`sectionCoverage`、`totalWords` 及 `insightText` 或与统计结果一致；不要添加耗时阈值断言。

## 风险与禁止项

- 最大风险是新谓词和 `extract` 的行边界或前导空白规则漂移。必须用显式期望值与等价断言同时覆盖 LF、CR、CRLF、Unicode newline、空标题、tab、非法 heading 和 fenced code。

- 禁止修改 `JournalSection.extract(from:)` 来让测试通过，禁止改变 fenced code 内标题的现有识别方式。
- 禁止把概览改为读取 summary、sections 或其他更重派生属性。
