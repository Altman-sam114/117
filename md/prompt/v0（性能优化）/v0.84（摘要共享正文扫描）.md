## 背景与证据

Mac Catalyst 长文编辑时，正文变更会更新 `JournalStore.entries`，随后列表行和编辑器重新评估。当前摘要派生仍有可以直接从源码证明的两次完整正文遍历：

1. [`MDJournal/Models/JournalEntry.swift:121-127`](../../../MDJournal/Models/JournalEntry.swift) 的 `JournalEntry.bodySummary` 创建 `JournalEntryBodySummary`。
2. [`MDJournal/Models/JournalEntry.swift:230-252`](../../../MDJournal/Models/JournalEntry.swift) 的 `JournalEntryBodySummary.init` 先在第 247 行创建 `JournalEntryBodyMetrics(body:)`。
3. `JournalEntryBodyMetrics` 在 [`JournalEntry.swift:199-208`](../../../MDJournal/Models/JournalEntry.swift) 调用 `JournalBodyDerivation.scan`；实际 Character/Index 循环位于 [`JournalEntry.swift:320-367`](../../../MDJournal/Models/JournalEntry.swift)，同时派生词数、小节和 `hasVisibleContent`。
4. 同一个 `JournalEntryBodySummary.init` 随后在第 249 行独立调用 `MarkdownSummaryText.plainText(from: body, removesListMarkers: false)`；该函数在 [`JournalEntry.swift:487-526`](../../../MDJournal/Models/JournalEntry.swift) 再次从头遍历正文并构造摘要。
5. [`MDJournal/Views/EntryRowView.swift:7-9`](../../../MDJournal/Views/EntryRowView.swift) 每次列表行 body 评估都创建 `bodySummary`，随后在 [`EntryRowView.swift:38-55`](../../../MDJournal/Views/EntryRowView.swift) 使用摘要、词数和小节数，在 [`EntryRowView.swift:69-97`](../../../MDJournal/Views/EntryRowView.swift) 使用小节结果。正文输入每次写回会经过 [`MDJournal/Stores/JournalStore.swift:83-95`](../../../MDJournal/Stores/JournalStore.swift)，因此该重复扫描会出现在高频列表重绘路径。

这不是 v0.78 的 metrics 内部重复，也不是 v0.80 的 overview 扫描或 v0.83 的 placeholder 扫描；本轮只解决“同一个 `JournalEntryBodySummary` 先派生 metrics、再重新扫描全文生成 excerpt”的重复工作。

## 本轮目标

1. 让 `JournalEntryBodySummary` 在一次 `JournalBodyDerivation` 正文扫描中同时取得当前需要的 metrics 和完整正文 excerpt。
2. 让 `JournalEntryBodySummary` 从这次共享结果构造 `JournalEntryBodyMetrics`，不再先调用 `JournalEntryBodyMetrics(body:)`、再调用独立的全文 `MarkdownSummaryText.plainText`。
3. 保持列表行现有的摘要、词数、小节数、小节标题和空正文显示行为，减少 Mac Catalyst 长文输入期间的重复正文遍历。
4. 保持现有 `JournalEntryBodyMetrics`、`JournalEntryBodySummary`、`JournalSection` 和兼容解码边界的外部行为；新增状态必须是非持久化派生数据。

## 非目标

- 不修改 `JournalStore` 的集合修改、保存 debounce、flush、revision、actor writer、错误仲裁或排序逻辑。
- 不修改 JSON 文件名、编码格式、字段、兼容解码或本地数据内容。
- 不修改 `MarkdownBlockParser`、`MarkdownPreviewView`、`MarkdownPreviewUpdateModel` 的解析、150ms debounce、latest-wins、entry ID 或焦点生命周期。
- 不修改 `MarkdownBodyTextView` 的 IME、marked text、正文写回、选区、Tab/Shift-Tab、回车续写、输入 traits 或 first responder 行为。
- 不修改 v0.79 的窗口/sidebar 尺寸、v0.82 的 ContentView 列表 snapshot、v0.83 的 `hasVisibleContent` 或现有 `EntryEditorView` 布局。
- 不引入跨 SwiftUI body 评估的缓存、计时阈值、分配阈值、第三方依赖、并发扫描或独立 native macOS target。
- 不为了本轮目标重写 Markdown 摘要算法、改变摘要文案、改变 `###` 小节识别或顺手重构无关代码。

## 架构边界

- `JournalEntry` 是模型和兼容 Codable 边界；本轮只增加非持久化 derivation 结果，不向 `JournalEntry` 增加 Codable 字段。
- `JournalBodyDerivation` 是正文 metrics 的内部单次扫描实现；共享 excerpt 必须留在该模型层边界内，不向视图暴露扫描器细节。
- `JournalEntryBodyMetrics` 继续是编辑器、统计和其他 metrics 消费者的值类型入口。
- `JournalEntryBodySummary` 继续是列表摘要的值类型入口；`EntryRowView` 只消费它，不自行扫描正文。
- `MarkdownSummaryText` 仍可能被 `JournalSection.excerpt` 使用。只有确认完整正文 summary 已改为共享结果后，才可清理无调用的代码；不得为了减少文件行数破坏小节 excerpt 语义。
- `JournalStore` 仍是唯一集合更新和 JSON 持久化入口。摘要共享扫描不得进入 Store 保存路径，也不得绕过 Store 修改日记。

## 摘要语义保持要求

共享扫描必须保持当前 `MarkdownSummaryText.plainText(from: body, removesListMarkers: false)` 的结果，而不是近似实现：

- 当前完整正文摘要会跳过 `#`、`*`、`` ` ``、`>` 等轻量 Markdown 标记；`removesListMarkers` 为 `false` 时，连字符仍按旧规则保留。
- 当前摘要按 literal `\n` 刷新行并合并非空行；不得未经验证地把所有 Foundation newline、Unicode scalar 或 `Character.isNewline` 替换为同一语义。
- 当前空结果回退为“还没有正文”；摘要正文、空行折叠、Unicode 字符、组合字符和 emoji 的输出均需保持。
- `JournalBodyDerivation.scan` 原有 word count、Foundation newline、小节 marker、空标题、EOF、fenced code 和 `hasVisibleContent` 语义必须保持。
- `JournalSection.excerpt` 仍以 section markdown 为输入，并保持其独立的 `removesListMarkers: true` 语义。
- 不允许用 `JournalEntryBodyMetrics.wordCount` 推导 excerpt，也不允许用 Markdown preview parser 的 block 输出替代摘要口径。

## 纯值 characterization 测试方案

在 `MDJournalTests/JournalEntryTests.swift` 增加一个明确锁定共享摘要结果的测试，例如 `testBodySummaryPreservesExcerptAndMetricsAcrossSharedScan`。测试只调用生产值类型，不创建 SwiftUI host、UITextView、模拟器、文件或真实 scheduler。

至少覆盖以下小数据案例：

- 空字符串、全空白和多行空白。
- `#` 标题、粗体、反引号、引用、普通连字符和任务列表。
- `###` 合法小节、空标题、非法 marker、连续小节和 EOF marker。
- LF、CRLF 与现有 Foundation newline 边界。
- 中文/英文混排、emoji、单独组合标记和组合字符。
- fenced code、空小节和含多行正文的长正文样本。

每个案例至少断言：

- `JournalEntryBodySummary(body:)` 的 `excerpt` 等于当前既有摘要口径的期望值。
- `summary.metrics` 与独立 `JournalEntryBodyMetrics(body:)` 的 `wordCount`、`sections`、`sectionCount`、`hasVisibleContent` 完全一致。
- `JournalSection.extract(from:)` 和 section excerpt 的既有结果没有改变。

行为测试不能单独证明扫描次数，因此 Agent B 的轻量静态检查和 Agent C 的 diff 复审还必须确认：`JournalEntryBodySummary.init` 只消费一次共享 derivation，不再同时执行完整 metrics 初始化和完整正文 `plainText` 扫描。禁止用“耗时下降”或本地 profiling 数字替代源码边界与纯值结果证据。
