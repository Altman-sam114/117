# Agent A 实现提示词：v0.77 / 正文小节流式派生

## 版本与起点


## 目标

优化 MDJournal/Models/JournalEntry.swift 中 JournalSection.extract(from:) 的长文派生路径：用单调 String.Index/Substring 逐行扫描，避免先用 Foundation components(separatedBy: .newlines) 物化整篇 [String] 行数组，减少不必要的逐行 String 临时对象。可保留当前 section 缓冲和最终 join/trim；不得宣称零分配。

输出必须与当前实现兼容：section 数量、顺序、 order、id、title、markdown、excerpt 均不变。首个合法标题前正文忽略；命中新标题先 flush；标题后的每行收集；连续 marker、空正文、无尾随换行和 EOF flush 语义不变。

## 兼容边界

必须继续识别行首连续 ASCII 空格和 tab 后的精确 marker：### 加一个 ASCII 空格。### 无空格、### 加 tab、####、行内 marker、非 ASCII 空白前导均不改变现有结果。

必须保留空标题规则：标题按现有 String trimmingCharacters(in: .whitespacesAndNewlines) 语义裁剪，空标题为「未命名小节」。

必须保留 Foundation .newlines 的实际语义，包括 LF、CR、CRLF 和 CharacterSet.newlines 覆盖的 Unicode newline（现有测试涉及 VT、FF、NEL、LS、PS）。逐行扫描必须以现有 components 行为为 characterization 基线，正确处理 CRLF，不把 Unicode newline 当正文，也不擅自改变分隔行为。正文行仍以 "\n" join，再对整体执行相同的 String trim；不能保留原始 CR/LF，也不能新增或丢失边缘空白行。

不得引入 fenced code 状态机。当前 fenced code 中位于行首的 ### 仍按普通合法 marker 识别；不要根据围栏改变规则。不要复用可能有不同换行或代码块语义的 MarkdownBlockParser。

## 非目标

## 实现与测试

优先只改 JournalEntry.swift 和已有 MDJournalTests/JournalEntryTests.swift。用 String.Index 获取 Substring 行切片；用 CharacterSet.newlines 判定换行，并按旧 Foundation 语义处理 CRLF 和 EOF。只在命中标题或 flush 需要时创建 String。保留原 flush 的 order、joined(separator: "\n") 和整体 trim。

允许补充精确 characterization 测试，必须断言 count、title、markdown、order，而不只断言 extract 是否为空。覆盖 LF/CR/CRLF/混合及 VT/FF/NEL/LS/PS；ASCII 空格/tab、非法 marker、非 ASCII 空白；空标题、连续 marker、空正文、尾随换行、标题前正文；fenced code 中的合法 marker。不要写不稳定的耗时/分配断言。测试不能使用 SwiftUI host、模拟器、截图或真实 app。
