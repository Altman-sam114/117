# v0.95 / 手机导航与写作焦点

## 总目标与本轮位置

人工希望 iOS 写入优美、高效，全面优化 UI，并补齐隐私、设置、安全、高级订阅，准备 App Store 发布。Agent X 按有限三轮推进：v0.95 手机生产导航与焦点；v0.96 设置、隐私与本地数据安全；v0.97 真实订阅能力、现代 SDK Release/archive 与提交准备。后两轮必须在前轮 Agent C 下载最新 artifact 验收通过后，由 Agent A 另写提示词；本文件不授权提前实现它们，也不把工程完善等同于账户签名或 App Store 审核完成。

本轮完成标准是：手机从资料库点选日记、新建、返回、再次打开，形成可用的生产导航闭环；标题和正文的键盘“完成”、预览及写作命令按明确焦点规则工作。保持已有纸本、墨绿与中文工具型视觉，修复功能入口带来的布局问题，不重复重构 v0.93/v0.94 已完成的视觉系统。

额外纳入一个局部性能修正：分享载荷延迟到实际导出时生成，避免每次编辑器评估都拼接完整 Markdown；不因此扩展成持久化或预览性能重构。

## 目标与行为契约

### 1. iOS 16 兼容的手机导航

- 手机 compact width 使用原生 `NavigationStack` 与稳定 UUID value destination；iPad regular width 和 Catalyst 保留 `NavigationSplitView`。不能用 iOS 17+ API 升高最低版本来绕过问题。
- `ContentView` 继续是 selection、筛选与 detail binding 的唯一拥有者。`selectedEntryID` 仍唯一表示域选中；允许新增一个本地 presentation 标志，单元素 path 由选中 ID 与该标志派生，不能维护第二套日记数组、正文、筛选或相互漂移的 selection。
- compact 首次进入展示资料库；初始化/搜索/分类/Store 变更导致的 selection repair 不能被当成人工点选而自动 push。点击日记行由真实 `NavigationLink` 进入对应日记，系统返回和交互返回只改变 presentation，保留有效 selection。返回后可以再次打开相同日记。
- 点击任一新建入口时先清除搜索与分类筛选，调用既有 `JournalStore.createEntry()`，选中并展示真实新 ID，再进入它的编辑器；不允许“创建一篇却打开筛选中的旧篇”。这是明确的生产行为修正，README/flow/test 同步说明。原 `JournalEntrySelectionPolicy` 纯规则及隐藏 selection characterization 保留。
- 删除/筛选后 selected ID 仍按现有 `filteredEntries` policy 修复；可见结果为空时移除失效 detail。相邻导航只能在当前可见顺序中选择，首尾不循环。
- 紧凑/常规宽度往返时保持有效 selection 与当前日记内容，不把导航事件作为 Store mutation；不承诺跨不同系统导航容器保留同一个 UIKit 对象，但不得退化既有编辑器内部跨宽度身份和 UTF-16 回归。
- 保留 row 的 Equatable 可见投影、日期与 selected trait，保留 context menu、swipe 删除确认和 44pt 控件命中；`NavigationLink` 的视觉应与纸本资料库协调。

### 2. 标题与正文的焦点闭环

- 给标题添加明确的 SwiftUI 焦点绑定，不改变标题输入节点的结构位置，不用临时 UIKit 全局 responder 搜索代替状态协调。
- 键盘“完成”同时解除标题与正文焦点，保留正文及 UTF-16 选区；标题没有焦点时也不能意外重新聚焦正文。
- 进入预览时同时清除标题和正文焦点。由现有 Picker 返回编辑仍遵守 preserve；由预览命令返回编辑继续遵守 focus，不抢标题焦点。
- 专注写作、聚焦正文、Markdown 片段和缩进命令先清标题焦点，再走现有正文命令。标题与正文不能同时持有相互争抢的焦点意图。
- 保留中文 marked text、一次性正文/选区 token、Markdown continuation/indentation、字体、text traits 与 Store 写入链路。优先不修改 `MarkdownBodyTextView`，如因实测需要修改必须向 Agent X 说明证据和边界。

### 3. 分享载荷按需生成

- 使用 iOS 16 可用的自定义 `Transferable`，只持有 `JournalEntry` 值；在 `DataRepresentation` 导出 closure 执行时生成与 `entry.markdownDocument` 完全相同的 Markdown UTF-8 数据，保留分享 subject/title。
- 创建分享值、构造 toolbar 与正常输入过程中不得预先求值全文 Markdown/Data，不以另存一份全文缓存换取表面上的延迟。
- 在现有测试中补内容等价和 Unicode/空标题/多行正文导出样例；实际生产 representation 必须调用受测的同一导出 helper，不能测试另一份模板。用源码边界和确定性内容断言支撑结论，不编造延迟/分配测量。
- 不增加依赖，不修改 `JournalEntry.markdownDocument` 兼容语义，不移除原有免费单篇分享。
