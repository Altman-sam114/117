## 2. 当前问题与本轮目标

现有两列 `NavigationSplitView` 的 sidebar 同时承载大段概览、分类菜单和多层卡片。300pt 左右宽度下，每行包含日期、标题、摘要、小节清单及页脚，浏览成本高；列表缺少跨月的时间层级。编辑器在普通高度分别显示模式行、Markdown 工具栏，双栏又增加 pane header，正文纸面和外围缺少明确关系。v0.88 渲染附件只有一篇 starter 日记，不能评价真实资料库密度、月分组或完整主窗口。

本轮完成以下可见结果：

- 左栏成为紧凑资料库：简短集合摘要、明确分类入口、按年月分组的日记时间轴。
- 每篇日记使用轻量记录行，日期、标题和摘要先于次要指标；减少重复小节名称、层层圆角卡片和装饰。
- 编辑/预览成为具有留白、明确纸面边界和统一命令条的写作画布。低高度和辅助字号持续为正文保留空间。
- 以多篇、多月、长标题和长中文 fixture 产出真实生产视图渲染，Agent C 逐张查看，而非只新增布局常量测试。

视觉继续使用暖白、浅纸色、墨绿和原生中文排版；正文可保留 rounded 字体，标题保留现有 serif 方向。优先依靠字重、间距、时间分组和细线建立层级，不引入广告式 hero、饱和渐变或持续动画。无需为了“发布级”扩大标题字号或加入过场；确有过渡效果时必须尊重 Reduce Motion，并且不能作用于输入框身份或布局切换时序。

## 4. 架构依据与状态流

`ContentView` 继续持有 searchText、selectedCategory 和 selectedEntryID；同一次 body 的 `JournalEntryListSnapshot` 继续由列表、detail guard 和 focused navigation 共享，Binding getter/setter 继续实时访问 Store。

新增纯展示分组 helper（建议 `JournalEntryTimelineSnapshot`），输入只能是当前 `snapshot.filteredEntries` 与可注入的 Calendar。分组不重新搜索、不重新排序、不扫描正文。年月 key 来自注入 Calendar 的 month interval 或等价 DateComponents，不能来自本地化标题字符串；显示标题允许通过 Locale 格式化。生产 `EntryListView` 必须真实消费该 helper，不能只在测试中定义。

数据顺序仍为 Store 的 createdAt 新到旧顺序。对这个已有有序输入，组顺序及组内顺序都要保留，flatten 后的 ID 数组必须与 filteredEntries 完全一致。新建、删除、日期跨月更新、搜索/分类变化使用当前快照自然重建分组，不增加持久状态。月标题可显示“2026年10月 · 3篇”，计数仅来自当前可见结果。跨年同月不得合并，时区决定月边界，Locale 只改变标题，不改变分组身份。

编辑器继续由 `EntryEditorWorkspaceState` 唯一持有 mode、预览偏好、focus 和选区。仍使用实际 detail `>=1120pt && !isAccessibilitySize` 的双栏资格，`820pt` 保留原头部档位。1360pt 主窗口含 sidebar 时可以单栏；不为制造桌面截图而降低双栏阈值。

显示正文时，保留当前固定 HStack 中的正文节点位置。画布留白、宽度、边框和背景通过 modifier 调整，不按窄宽/高低分支复制编辑器，不使用 `.id(width)`、`.id(mode)` 或隐藏的第二个输入框。标题输入框也保持结构身份，保留 v0.89 的高度切换测试。

## 5. 具体界面要求

### 5.1 资料库与时间轴

1. 将当前“MD JOURNAL / 留住每一天。”大概览改为短集合摘要，普通字号下以应用/资料库名称、篇数/词数、必要连续天数为主。分类仍使用绑定到父级状态的原生菜单或 Picker，44pt 最小交互区与可访问性文案保留。
2. 标准 300–320pt 左栏、720pt 高度、普通字号下，概览与筛选在首个年月标题之前应明显收敛，目标不超过约 150pt；不要使用固定高度裁切来满足目标。Accessibility 字号允许自然增高和滚动。
3. 使用真正的 List Section 表达年月分组。每个 entry 仍保留 `.tag(entry.id)`、`.contextMenu`、`.swipeActions`，删除继续进入现有 `JournalDeletionConfirmationState`；原生 List selection、上下浏览和 Mac 较新/较早快捷键不可退化。
4. 重排 `EntryRowView` 为轻量记录行：日期、标题、最多两行摘要，以及一行次要分类/词数信息；心情可作为有语义图标，普通字号不再展开前三个小节名称。减少重复框线，使用清晰的选中底色、短强调线或勾选，至少保留一种非颜色选中线索及 `.isSelected` trait。
5. 普通字号在 300–320pt 侧栏内，一般短标题行目标约 116–144pt；这是视觉方向，不是固定高度。长标题可用两行；辅助字号允许完整标题、元数据垂直排列和自然增高，不能 horizontal infinite proposal 后假装换行。
6. 空集合与筛选空结果仍清楚区分，保留“写一篇”和“清除筛选”。分类计数仍来自完整集合，组计数来自可见集合，不能混用。

### 5.2 写作画布

1. 以语义 canvas 背景包围 paper。普通宽屏采用克制的水平/垂直留白和细边界，标题、正文和状态信息有统一的阅读对齐；窄屏/低高度减少外围留白，把空间交给文字。不要在已有正文内部再嵌套垂直 ScrollView。
2. 保留 760pt 单栏正文阅读上限；双栏净宽仍扣 Divider 后等分、预览保持既有阅读宽度。不要因纸面 padding 让实际正文在窄屏变得过窄。
3. 合并重复模式/工具层：正常单栏使用一条清晰命令带容纳编辑/预览切换、可见常用格式动作和溢出菜单；窄屏、低高度及 Accessibility 使用模式切换加 Markdown 菜单。所有 Markdown 片段仍能访问，按钮仍有 44pt 命中区、help 和 label。可以使用 ViewThatFits，但不能为每个候选内容创建正文输入框。
4. 双栏 pane 标识保持简短，避免 pane header、模式条、完整九按钮工具条三层同时堆叠。Mac 顶部原有专注、写作工具、预览和分享仍可见且继续走同一 command/state 入口。
5. 收起详情时应能看到日期与必要分类/心情摘要，点击详情仍可编辑日期/分类/心情和查看小节目录；标题继续是最强视觉层级。已有头部最多占可用高度 38%、低于 400pt 的紧凑标题/工具菜单/隐藏状态栏规则继续有效。
6. 专注写作仍收起详情并隐藏预览、聚焦正文。浅色、深色、高对比及辅助字号使用语义颜色，不用硬编码白色纸面覆盖深色。

### 5.3 预览、统计和空态连贯性

结合新资料库和画布审查 `MarkdownPreviewView`、`StatisticsDashboardView`、`EmptyStateView`。如果存在明显不一致，针对纸面背景、细线、间距、标题层级和按钮样式做小范围统一。预览应继续连续阅读，统计总览继续完整宽度和辅助字号单列，空态继续表达下一步动作；不改其业务、统计口径、parser 或调度，不为追求“全面”制造无必要 diff。mode Picker、Markdown 菜单、详情入口和 Mac 工具栏要有明确中文 label/value/help，不能仅用无标签图标表达状态。
