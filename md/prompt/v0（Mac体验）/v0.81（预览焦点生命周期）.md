## 背景

当前 EntryEditorView 同时维护编辑/预览模式和正文焦点状态：

- mode 决定 compact 布局显示编辑器还是 MarkdownPreviewView。
- editorFocused 通过 MarkdownBodyTextView 的 binding 控制正文 UITextView 是否成为 first responder。
- compact 模式的 Picker 可以直接改变 mode；Mac Catalyst 现有 ⌘⌥P 通过 togglePreviewVisibility() 改变同一个状态。
- 进入 compact 预览时，当前路径只改变 mode，没有把 editorFocused 明确设置为 false。如果此前已经有异步 becomeFirstResponder() 排队，预览切换后还可能出现过期焦点请求。
- 从 compact 预览通过现有 ⌘⌥P 回到编辑时，当前路径也没有明确请求正文焦点；直接从 Picker 选择“编辑”与快捷命令返回编辑的意图没有区分。
- MarkdownBodyTextView.updateUIView 是 UIKit bridge：它消费 SwiftUI binding，按需同步正文、UTF-16 选区和 first responder 状态；它不能自行读取 EntryEditorView.mode，也不能成为第二套模式状态源。

本轮不重复 v0.79 的主窗口/sidebar 尺寸，也不新增快捷键。目标是让“预览中不持有正文焦点”“快捷命令回到编辑即可继续写”“直接 Picker 回编辑不抢焦点”成为明确且可测试的状态契约。

## 目标

1. 在 compact/窄屏布局进入 .preview 时清除正文焦点，使 editorFocused 变为 false，并允许 MarkdownBodyTextView 结束或拒绝过期的 first responder 请求。
2. 通过现有 ⌘⌥P 从 compact 预览返回编辑时，请求正文焦点，使用户可以立即继续写作。
3. 直接通过 compact 模式 Picker 从“预览”选择“编辑”时，不强制调用 becomeFirstResponder()；保持未聚焦状态，用户点击正文后再开始输入。
4. 仅改变 compact 模式的焦点状态转移。宽屏 isPreviewColumnVisible、双栏编辑/预览结构和现有“专注写作”行为保持不变。
5. 使用最小的内部 EntryEditorFocusPolicy 纯值契约表达上述转移，并通过 XCTest 锁定确定性语义，不把纯值测试描述成真实 Mac first responder 验收。
6. 保持 iOS/iPadOS 的编辑、预览、正文 binding、选区、IME 和保存链路兼容；不改变 Markdown 内容或持久化数据。

## 架构与状态边界

### EntryEditorView

- EntryEditorView 是编辑器模式、compact/wide 布局、正文焦点和现有写作命令的边界。
- mode == .preview 只代表 compact 预览内容显示；它必须与正文 first responder 状态一致，进入预览后不能继续请求正文焦点。
- focusBody() 是现有正文聚焦入口，负责回到编辑并设置 editorFocused = true；从 compact 预览经 ⌘⌥P 返回编辑时应复用它，而不是复制一套焦点逻辑。
- 直接 Picker 选择 .edit 不应调用 focusBody()，只改变模式并保持未聚焦状态。
- togglePreviewVisibility() 的 wide 分支只切换 isPreviewColumnVisible，不得通过本轮 policy 改写宽屏焦点或预览列行为。

### MarkdownBodyTextView

- MarkdownBodyTextView 继续是 UIViewRepresentable 的 UIKit bridge，只消费 text、selectedRange 和 isFocused 三个 binding。
- updateUIView 可以按 binding 请求 becomeFirstResponder() 或 resignFirstResponder()，但必须以最新的 isFocused 为准；不能读取 EntryEditorView.mode、调用菜单 action 或保存自身模式状态。
- 如果本轮需要调整异步 first responder 调度，必须让较新的 isFocused == false 使旧的 becomeFirstResponder() 请求失效，避免进入预览后被过期闭包重新聚焦。不得用固定延时掩盖竞态。
- 不得在 preview View、MarkdownBodyTextView delegate 或 JournalStore 中重复维护另一份“当前模式”或“应该聚焦”状态。
- 不改变 marked text/IME、正文差异同步、选区 clamp、普通输入直接写回、Markdown 回车续写和 Tab/Shift-Tab 规则。

### 最小 EntryEditorFocusPolicy 纯契约

在现有 MDJournal/Views/EntryEditorView.swift 中增加最小内部纯值契约，优先不新增工程文件。实现可以使用等价命名，但必须能表达以下三种 compact 转移：

~~~
internal enum EntryEditorFocusPolicy {
    enum Transition: Equatable {
        case enterPreview
        case returnToEditFromPreviewCommand
        case selectEditModeFromPicker
    }

    enum Action: Equatable {
        case resign
        case focus
        case preserve
    }

    static func action(for transition: Transition) -> Action
}
~~~

语义必须固定为：

- enterPreview -> .resign；
- returnToEditFromPreviewCommand -> .focus；
- selectEditModeFromPicker -> .preserve。

该 policy 只描述 compact 模式的纯状态转移，不调用 UIKit、不访问 Binding、不派发异步任务、不读取实时窗口宽度。wide 预览栏不经过该 policy。
