# v0.68（键盘切换日记）

## 版本分配依据

- 当前最新已闭环正式版本为 `v0.67`，已完成正文输入直接写回性能优化。本轮继续服务 Agent X 总目标中的 Mac Catalyst 长时间写作体验，补齐正文聚焦时不离开键盘切换日记的桌面导航能力，因此沿 `v0.x` 小版本递增为 `v0.68`。
- 本轮是受限的 Mac 菜单、键盘导航和纯规则测试增量，不改数据模型、持久化、排序、筛选或编辑器布局，不开新大版本。

## 背景

`MDJournalApp` 已在 scene level 注册“日记”、“写作”和“插入 Markdown”菜单，`ContentView` 通过 focused scene value 暴露新建日记与显示统计动作，`EntryEditorView` 暴露正文聚焦、专注写作、缩进和预览动作。但当 `MarkdownBodyTextView` 是 first responder 时，用户仍需要离开键盘到侧栏点击，才能在日记之间切换。

`JournalStore.entries` 的现有合同是按 `createdAt` 从新到旧排列：新建日记插入首位，加载与修改日期时由 `JournalStore.sortEntries()` 按降序维护。因此方向必须使用无歧义的“较新日记”和“较早日记”：

- 较新：当前 index `- 1`；
- 较早：当前 index `+ 1`；
- 首项的“较新日记”禁用，尾项的“较早日记”禁用，不循环。

快捷键选用 `⌘⌥↑` 和 `⌘⌥↓`。上下箭头与列表中从新到旧的空间方向一致，也不与现有 `⌘N`、`⌘⌥E`、`⌘⌥W`、`⌘⌥[`、`⌘⌥]`、`⌘⌥P` 或 Markdown 字符快捷键冲突。

## 本轮目标

- 在“日记”菜单中增加“较新日记”和“较早日记”命令。
- 为两个命令分配方向清晰的 `⌘⌥↑` 和 `⌘⌥↓`，在 Mac Catalyst 正文聚焦时仍可执行。
- 严格依赖 `JournalStore.entries` 当前从新到旧的数组顺序；较新取 `index - 1`，较早取 `index + 1`，纯导航规则不自行排序。
- 首尾边界禁用对应菜单项，不循环；空列表、单篇、`nil` selection 和失效 selection 都不导航。
- 抽取无 SwiftUI 视图状态侜用的纯导航规则，并用确定性 XCTest 覆盖方向、边界和异常 selection。
- 用一个最小 focused scene action value 同时传递较新/较早两个可选动作；某方向不可达时对应动作为 `nil`，菜单必须据此禁用。
- 增加导航命令标题、方向、快捷键元数据与全局唯一性测试。
- 将 workflow 结果包版本更新为 `v0.68`，同步受影响文档，完成 `main -> origin/main -> GitHub Actions artifact -> Agent C` 验收闭环。

## 非目标

- 不改变 `JournalStore.entries` 的 `createdAt` 降序规则，不在导航 helper 内排序、复制或筛选 entries。
- 不让导航基于 `EntryListView` 的搜索结果或分类筛选结果；导航始终使用 `JournalStore.entries` 完整当前顺序。
- 不循环，不在边界时保持菜单可用，不把无结果操作实现成静默无操作的仍可用命令。
- 不实现“上一篇/下一篇”歧义文案，不增加日记切换工具栏按钮、侧栏箭头或 iOS 键盘附件栏入口。
- 不在切换前调用 `flushPendingSave()`、不额外保存、不修改 debounce，不新增脏状态或保存提示。内存中的当前编辑内容已由现有 binding 即时写回 Store，导航不应触发额外持久化。
- 不调用 `focusBody()`、不显式改变 `editorFocused`、不增加新的焦点请求，不通过 `.id(...)` 强制重建编辑器。切换只更改 selection，保持现有正文聚焦状态和 `EntryEditorView.onChange(of: entry.id)` 的选区置尾语义。
- 不保存每篇日记的光标位置，不改变现有切换 entry 后选区修复到新正文末尾的行为。
- 不修改 `JournalEntry` Codable 字段、JSON 文件名、加载/创建/更新/删除/保存行为、Markdown 规则、预览、统计或 UI 主题。
- 不引入第三方依赖、native macOS target、新 deployment target、UI test target 或性能阈值测试。
- 不在本机运行 build、XCTest、模拟器或 app；本轮完整构建和测试只使用 GitHub Actions 回传结果包验收。

## 架构依据与目标状态流

### 架构依据

- `JournalStore` 继续是日记集合与持久化的唯一修改入口；本轮导航不修改 Store，只读 `entries`。
- `ContentView` 已负责应用级导航、`selectedEntryID` 与选中项修复，因此应由它根据当前 entries 与 selection 构造可用动作并只更改 `selectedEntryID`。
- `MDJournalApp.JournalCommands` 是 scene-level 菜单和快捷键入口，只消费 focused action，不读 Store、不复制选中规则。
- `EntryListView` 的搜索/分类状态是列表展示边界，不应进入 scene command 导航规则。
- `EntryEditorView` 已在 `entry.id` 改变时将选区修复到新正文末尾；本轮不改此规则，也不让菜单绕过 `ContentView` 直接操作编辑器。

### 纯导航规则

新增一个不持有 SwiftUI `@State`、不读写 Store、不发起保存的纯规则，建议形状：

```swift
enum JournalEntryNavigationDirection: String, CaseIterable, Identifiable {
    case newer
    case older

    var id: String { rawValue }
    var title: String { ... }
}

enum JournalEntryNavigation {
    static func destinationID(
        in entries: [JournalEntry],
        selection: JournalEntry.ID?,
        direction: JournalEntryNavigationDirection
    ) -> JournalEntry.ID? { ... }
}
```

规则必须：

1. `selection == nil` 立即返回 `nil`。
2. 使用 `firstIndex(where:)` 在当前 entries 中定位 ID；失效 ID 返回 `nil`。
3. `.newer` 只尝试 `index - 1`，`.older` 只尝试 `index + 1`。
4. 目标 index 越界返回 `nil`，不取模、不回到另一端。
5. 返回目标 entry ID，不修改、排序或复制 entries，不接收筛选快照。

### Focused scene action value

只新增一个 focused value key，建议用一个内部值封装两个可选动作：

```swift
struct JournalEntryNavigationActions {
    let selectNewer: (() -> Void)?
    let selectOlder: (() -> Void)?
}
```

`ContentView` 在每次渲染时用纯规则分别求出两个目标 ID：有目标才提供只将 `selectedEntryID` 设为该 ID 的闭包，无目标则对应字段为 `nil`。`JournalCommands` 只消费这一个 focused value：

- “较新日记”执行 `selectNewer`，并在该闭包为 `nil` 时 `.disabled(true)`；
- “较早日记”执行 `selectOlder`，并在该闭包为 `nil` 时 `.disabled(true)`。

不得只传一个永远存在的 `(Direction) -> Void` 而让菜单在边界保持可用；也不必为两个方向各注册一个 focused key。

### 目标执行流

```text
Mac Catalyst 正文 first responder
-> “日记”菜单 / ⌘⌥↑ 或 ⌘⌥↓
-> JournalCommands 读取 focused JournalEntryNavigationActions
-> 对应可选动作存在时执行
-> ContentView 将 selectedEntryID 设为纯规则返回的相邻 ID
-> selectedEntryBinding 切换到目标 JournalEntry
-> EntryEditorView 保留现有编辑聚焦状态，并按现有 onChange 将选区修复到新正文末尾
```

边界流：

```text
空列表 / 单篇 / nil selection / 失效 selection / 方向越界
-> JournalEntryNavigation.destinationID == nil
-> 对应 focused action == nil
-> 对应菜单项 disabled
-> selectedEntryID、焦点、Store 和文件均不变
```

## 快捷键元数据设计

为避免菜单内硬编码和测试复制，导航方向应暴露标题，并新增可测的 `JournalEntryNavigationShortcut`（可与纯规则放在同一 utility 文件中）：

- `.newer.title == "较新日记"`，`keyEquivalent == .upArrow`，`modifiers == [.command, .option]`，`displayText == "⌘⌥↑"`；
- `.older.title == "较早日记"`，`keyEquivalent == .downArrow`，`modifiers == [.command, .option]`，`displayText == "⌘⌥↓"`。

shortcut 应提供稳定 `identifier`。箭头 identifier 可使用 `upArrow` / `downArrow` 令牌与 modifiers 组合，但必须能与现有 `EditorWritingCommandShortcut.identifier` 和 `MarkdownSnippetCommandShortcut.identifier` 在测试中进行唯一性比较。不要用本地化的 `displayText` 作为唯一标识。

## XCTest 要求与验收标准

### 纯导航规则

GitHub Actions 必须实际执行并通过新增导航测试。建议用清晰测试名称，至少包含：

- `testNavigationMovesToNewerAndOlderEntriesUsingCurrentOrder`
- `testNavigationStopsAtNewestAndOldestEntriesWithoutWrapping`
- `testNavigationReturnsNilForEmptySingleAndInvalidSelections`
- `testNavigationCommandMetadataAndShortcuts`
- `testNavigationShortcutsAreUniqueAcrossJournalWritingAndMarkdownCommands`

要求：

- 断言具体 ID，不只断言非 `nil`；
- 较新/较早方向与 `index - 1` / `index + 1` 一致；
- 首尾均断言 `nil`，显式防止循环回绕；
- 空、单篇、`nil` selection 和失效 selection 都覆盖两个方向；
- 快捷键元数据要检查 KeyEquivalent、modifiers、display text 和 identifier；
- 唯一性测试必须同时纳入导航、写作、Markdown 和保留的 `⌘N`，不能只检查新组内部。

### 命令 wiring 与用户可见行为

- “日记”菜单显示“较新日记”与“较早日记”，并显示 `⌘⌥↑` / `⌘⌥↓`。
- 中间日记两个命令均可用；最新日记禁用较新，最早日记禁用较早；单篇、空列表、`nil` 或失效 selection 两个都禁用。
- 正文聚焦时按快捷键可切换 selection，不需先点击侧栏；切换后不主动取消正文聚焦，新正文选区依现有规则到末尾。
- 导航不保存、不修改正文、不修改排序/筛选/JSON。

本轮不新增 UI test target，因此 focused scene value 路由、Mac Catalyst commands 编译和 KeyEquivalent 接线由云端 Mac Catalyst build 验证；纯导航规则与元数据由 XCTest 验证。真实菜单 disabled 视觉、正文 first responder 持续性和键盘事件分发仍需人工 Mac Catalyst UI 交互复核，不得用 build 或纯规则测试冒充该结论。

## 风险

- 纯 XCTest 能证明相邻 ID 规则和快捷键元数据，Mac Catalyst build 能证明 commands/focused value/KeyEquivalent 可编译，但两者都不能证明真实 `UITextView` first responder 下的菜单事件分发、焦点持续性或菜单 disabled 视觉；这些保留为人工 Mac UI 验收项。
- focused scene value 的可用性随 `store.entries` 和 `selectedEntryID` 重算。实现若把旧 index 或旧数组长期缓存到闭包，可能在日期更改、删除或创建后指向错误日记；建议闭包只捕获当前解析出的目标 ID，并依赖 SwiftUI 在状态改变后重新生成 action value。
- 现有 `JournalStore.sortEntries()` 仅比较 `createdAt`，相同日期的相对顺序由当前 entries 决定。本轮纯规则应忠实使用当前数组顺序，不自行添加 tie-breaker 而改变产品行为。
- 菜单方向文案与箭头方向必须一致：当前列表是新到旧，上箭头是较新，下箭头是较早。不得因“上一篇/下一篇”命名习惯反转偏移。
